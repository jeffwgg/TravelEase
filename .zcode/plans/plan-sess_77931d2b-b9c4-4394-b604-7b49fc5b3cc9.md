# Why sign-to-text accuracy is very low — diagnosis + fix plan

## Diagnosis (all verified in code)

The model (`model.tflite`, 39 MB) was parsed directly: input **`[1, 543, 3]`** float32, output `[250]`, pure MLP (1629 → 5796 → 1024 → 512 → 512 → 256 → 250). The label map is byte-for-byte the **Kaggle GISLR competition's** 250-class map (confirmed by user). Four defects in the inference path make the model output garbage:

1. **Only frame 0 of every gesture window is ever inferred on.** The extractor buffers a motion-gated window, resamples to 32 frames (52,128 floats) and calls `predictGesture` — but `_reshapeInput` (`asl_tflite_service.dart:192-198`) silently truncates to the model's 1,629 elements. The model is single-frame; the app treats it as temporal.

2. **Landmark layout mismatch.** `_buildLandmarkTensorFromFrame` (`camera_landmark_extractor_service.dart:503-527`) writes pose → indices 489–521, hand → 522–542, face block 0–488 all zeros (MediaPipe Holistic order). The Kaggle GISLR dataset orders landmarks **pose 0–32, left hand 33–63, right hand 64–93, face 94–542** — so the model reads pose/hand coordinates out of face slots and zeros out of its pose/hand slots.

3. **Normalization is an admitted guess.** `_preprocessWindow` (`camera_landmark_extractor_service.dart:587-626`): "⚠️ BEST-GUESS preprocessing (the model's training preprocessing is unknown)" — per-window z-score. The Kaggle dataset feeds raw MediaPipe coordinates (x,y normalized 0–1, z as-is, 0/NaN for missing landmarks).

4. **Only one hand, never the left-hand slot** (`camera_landmark_extractor_service.dart:521-524`), so left-handed signing is systematically wrong.

**Net effect:** the built-in sanity probe (`camera_landmark_extractor_service.dart:553-571`) detects the degenerate output ("MODEL SUSPECT") and auto-disables the TFLite path — so nearly all output comes from the ~30-sign geometric rule engine. That's why accuracy is very low.

## Implementation

**Step 1 — Fix landmark layout** (`camera_landmark_extractor_service.dart:498-527`)
Rewrite `_buildLandmarkTensorFromFrame` to Kaggle GISLR order: ML Kit pose (33 pts, order already matches) → indices 0–32; detected hand → 33–63 for a left hand, 64–93 for a right hand (use MediaPipe `Hand` handedness if the plugin exposes it, else nearest-wrist-to-pose heuristic); face 94–542 stays zero (documented limitation). Correct the misleading comment at lines 498–502.

**Step 2 — Remove the guessed normalization** (`camera_landmark_extractor_service.dart:587-626`)
Delete per-window z-scoring; feed raw coordinates exactly as the dataset: x,y in [0,1] (both MediaPipe and ML Kit already output this), z as-is, zeros for missing landmarks. Keep the mirror compensation already applied in `_buildFrameData`.

**Step 3 — Single-frame inference + window aggregation** (`asl_tflite_service.dart`, `camera_landmark_extractor_service.dart:529-583`)
- Add `predictFrames(List<List<double>> frames)` to `AslTfliteService`: runs the model once per frame, averages softmax probabilities across frames, returns argmax + mean confidence. Replace the dead `predictWindow` (never called).
- Make `_reshapeInput` throw/log loudly on size mismatch instead of silently truncating 52,128 → 1,629 (the core truncation bug).
- `_runTemporalInference`: resample the closed window to ≤32 evenly-spaced frames (cost control), call `predictFrames`. Keep the 0.60 confidence gate and the sanity probe (they'll now guard a correctly-fed model).

**Step 4 — Make TFLite accuracy measurable** (`sign_accuracy_evaluator.dart`)
Extend the evaluator (currently geometric-only) to replay recorded clips through the new per-frame TFLite path with the same majority-vote scoring, so layout/normalization correctness is validated by measured top-1 on clips recorded via the existing debug clip recorder.

## Out of scope (per your choice)
- Geometric fallback tuning, pose-missed-frame gate, left-hand UX, UI text behavior (replace + 1.5 s auto-clear), vocabulary mapping (`thank_you` vs `thankyou`; `bus`/`flight` absent from the 250 map).
- Known limitation documented but not fixed: face block (94–542) is always zero — the app has no face mesh, so accuracy will sit below the model's Kaggle benchmarks; geometric path remains as fallback.
